How the pieces fit
  1. Sources

    PS is the top authority. ES sits beside it. Four more baseline documents plus the scenario matrix follow, then twelve downstream documents and an ADR set, each gated by the last one's readiness verdict.

  2. Requirements

    What the system must do and must never do. Objectives, security, non-functional, acceptance, and the twenty hardening items.

  3. Components

    The per-request pipeline, the intelligence modules that steer it, the state machinery that makes a request resumable, and the governance parts that can block anything.

  4. Techniques and capabilities

    The named optimizations, the cache types, the developer-agent modules, and the optional serving-layer capabilities.

  5. Build order and proof

    When to build each thing, and how proven it is.

  6. Vocabulary

    Words and tags that repeat across every document.

Three scales that look alikeBuild priority P0 to P5 says when to build. Maturity Level 0 to 5 says how proven it is. Test priority P0 to P3 says how risky a scenario is to leave untested. They are unrelated.
Two failure rulesOptimization stage fails: fall back to the original path and continue. Security or authorization fails: reject the request.
